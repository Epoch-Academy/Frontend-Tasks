# 第 6 周任务：社团招新平台 v0.2 —— 组件化重构

## 任务目标

把 v0.1 的单页改造成组件化版本，掌握组件拆分、Props、Emit、插槽、生命周期和基础 Composable，并保证原有功能不退化。

## 指引

重点关注以下内容：

- 根据界面职责和复用需求拆分组件；
- Props 类型、默认值和单向数据流；
- Emit 与自定义事件；
- 默认插槽和具名插槽；
- 组件 v-model 的基础用法；
- （选做）模板引用 `ref`：弹窗打开后让内部第一个可聚焦元素获得焦点；
- `onMounted`、`onUnmounted` 生命周期；
- `scoped` 样式与公共样式；
- 使用 Composable 复用状态逻辑。

不要为了数量把每一个标签都拆成组件，也不要让子组件直接修改父组件传入的 Props。

## 本轮要求

1. 在现有项目上重构，至少拆分出 **5 个职责明确的组件**，例如：
   - `AppHeader`：顶部标题 / 导航；
   - `ClubFilter`：搜索、分类、排序（用 props + emit 或组件 `v-model` 回传条件）；
   - `ClubList`：列表容器；
   - `ClubCard`：单张社团卡片；
   - `BaseModal`：通用弹窗（使用插槽）；
   - `EmptyState` / `StatusPanel`：空状态面板（使用具名插槽）。
2. 父组件 `App.vue` 持有列表数据、筛选条件和弹窗状态；子组件只通过 **Props 向下、Emit 向上** 通信，**子组件不得直接修改 Props**。
3. `ClubCard` 通过 Props 接收 `club` 和「是否已收藏」，通过 `emit` 通知父组件「收藏 / 取消收藏」和「查看详情」。
4. 新增「社团详情弹窗」：点击卡片打开弹窗，展示该社团的完整信息。**这不是新增业务能力，而是把 v0.1 里已有的数据换一种呈现方式**（数据仍来自 `src/data/clubs.js`，不加接口、不加字段）——它是本周唯一允许新增的界面，弹窗之外不要再加别的功能。
5. 弹窗必须建立在一个**通用弹窗组件**上，本周统一叫 **`BaseModal`**：
   - 默认插槽承载主体内容、具名插槽承载标题和底部操作，内容由父组件决定；
   - 具体展示「某个社团详情」的组件可以自行命名（示例里叫 `ClubDetailModal`，即 `BaseModal` 的一种具体用法），但 `BaseModal` 本身要能脱离社团场景复用；
   - 不要在父组件里手写一遍遮罩层 + 定位样式的重复结构。
6. 弹窗打开后按 `Esc` 可以关闭：使用 `onMounted` / `onUnmounted` 注册并清理全局键盘事件。
7. 把 v0.1 里散落的收藏读写逻辑抽成 `src/composables/useFavorites.js`，对外暴露收藏列表和切换 / 清空方法。
8. 使用 `scoped` 样式，保证组件之间样式互不污染。
9. 保留 v0.1 的搜索、分类筛选、排序、统计、收藏持久化和空状态，**功能不得退化**。

## 完成标准

- 组件拆分符合职责，而不是所有逻辑仍然堆在 `App.vue` 中；
- Props 声明清晰，子组件没有直接修改 Props；
- 收藏和打开详情通过自定义事件正确通知父组件；
- 插槽组件被实际使用，内容能够由父组件传入（`BaseModal` 通过默认插槽 + 具名插槽承载内容，没有在父组件里重复写遮罩结构）；
- 弹窗键盘事件在组件卸载时得到清理（打开 / 关闭弹窗多次后，按一次 `Esc` 只触发一次关闭，没有残留监听）；
- 搜索、筛选、排序、收藏和结果统计仍能正确联动，与 v0.1 行为一致；
- 刷新页面后收藏状态仍能恢复；
- 能现场根据组件树说明 Props 向下、事件向上的数据流，以及 `useFavorites` 解决的问题。
