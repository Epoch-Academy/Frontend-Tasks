# 第 8 周任务：社团招新平台 v1.0 —— 路由化 SPA（结业项目）

> 本周是主线项目的收尾。在 v0.3 的基础上引入 Vue Router，把单页拆成多视图 SPA，并实现登录与个人中心。**第 8 周的结业项目就是这个持续迭代了 4 周的项目，不是新项目。**

## 上周回顾（v0.3）

你现在应该已经有一个能对接接口的项目：

- 统一 API 层（`src/api/request.js`、`club.js`、`activity.js`）；
- 异步 Composable（`useClubs`、`useActivities`）与完整的加载 / 空 / 失败 / 重试状态；
- 活动列表 + 报名表单（校验、提交中、防重复、名额判断）；
- `provide` / `inject`、环境变量与开发代理；
- v0.2 的组件与 `useFavorites` 继续复用。

本周把这一整套能力搬进一个多视图 SPA。

## 任务目标

使用 Vue 3 与 Vue Router 4 把主线项目改造成多视图单页应用，掌握路由配置、动态参数、查询参数、嵌套路由、导航守卫、404 页面和路由懒加载。

## 指引

重点关注以下内容：

- SPA 与前端路由的基本工作方式；
- `createRouter`、`createWebHistory` 和路由表；
- `RouterLink`、`RouterView` 与激活状态；
- `useRoute`、`useRouter` 和编程式导航；
- 动态路由参数、查询参数及其区别；
- 嵌套路由、重定向、路由元信息和 404；
- 全局前置守卫与简单登录状态模拟；
- 页面级组件懒加载；
- History 模式部署回退的基本概念。

- **默认做法：复用第 7 周已经在用的真实登录。** 第 7 周你接的是仓库根目录的真实 `后端服务/`（Express + SQLite），它已经提供 `POST /api/auth/login` 与 `GET /api/auth/me`，第 7 周的示例也把 `src/api/auth.js` 和 `src/composables/useAuth.js` 准备好了；个人中心再调 `GET /api/registrations/me` 展示「我的报名」。

本项目**不要求你自己实现后端、数据库或权限系统**。

## 本轮要求（主线项目增量）

1. 安装并配置 Vue Router 4（`createRouter` + `createWebHistory`），把 v0.3 的单页拆成页面级组件（views）。
2. 至少配置以下页面与路由：
   - 首页 `/`；
   - 社团列表 `/clubs`（复用 v0.3 的列表与筛选组件）；
   - 动态社团详情 `/clubs/:id`；
   - 活动列表 `/activities`（复用 v0.3 的活动与报名组件）；
   - 登录页 `/login`；
   - 个人中心 `/user`（父路由）；
   - 个人中心的资料 `/user/profile` 与收藏 `/user/favorites` 两个**嵌套**子页面；
   - 404 页面。
3. 顶部导航使用 `RouterLink`，当前页面应具有可识别的激活样式。
4. 社团列表的搜索 / 分类条件使用 `query` 保存；刷新页面后筛选条件可以从地址栏恢复。
5. 社团卡片通过动态路由进入对应详情页；不存在的 `id` 必须显示合理提示或跳转 404。
6. 至少使用一次编程式导航，例如登录成功后跳转、报名后前往个人中心或点击按钮返回列表。
7. 个人中心及其子页面需要登录后访问：使用路由 `meta` 和全局前置守卫实现访问限制。
8. 未登录访问受限页面时跳转到登录页，并记录原目标地址；登录成功后返回原目标地址。
9. 实现退出登录，退出后再次访问受限页面仍应进入登录流程，且不出现重定向死循环。
10. 页面级路由组件使用动态 `import()` 进行懒加载，首页是否懒加载可自行决定。
11. 404 页面提供返回首页或社团列表的入口。
12. **选做：**为 `/clubs` 添加别名 `/clubs/all`，观察两个地址打开同一页面时地址栏是否变化，并与重定向进行对比（重定向会改地址，别名不会）。不做此项不影响结业验收。
13. 页面刷新后登录状态可以合理恢复（接了真实后端就调 `GET /api/auth/me` 验一次；用模拟登录则从 `localStorage` 恢复）；本地损坏数据不能导致应用白屏或无限跳转。
14. 复用第 7 周的 API 层、请求状态、`useFavorites` 与第 6 周的组件；保证加载、空数据和错误状态完整，控制台无明显路由警告。**报名表单沿用第 7 周「报名接口契约」的字段与校验（`activityId`、`name`、`studentId`、`contact`、`reason`，理由不少于 10 个字）**，路由化之后 400 / 404 / 409 的提示仍要分别生效，不能因为搬进新页面就退化成统一「提交失败」。

## 完成标准

- 执行 `npm install`、`npm run dev` 后项目可以正常运行，`npm run build` 成功；
- 所有必做路由均可通过界面进入，浏览器前进和后退行为合理；
- 动态详情页能根据 `id` 展示对应数据，异常 `id` 得到处理；
- 列表查询条件与 URL 中的 `query` 正确同步；
- 嵌套路由通过子级 `RouterView` 正确展示；
- 未登录用户无法直接进入个人中心，登录后能回到原目标页面；
- 退出登录、页面刷新和 404 场景行为正确，不出现重定向死循环；
- 页面级组件按要求懒加载，路由配置结构清晰；
- v0.3 已有的接口数据、报名表单、收藏功能在路由化后仍然可用；
- 项目没有阻断使用的控制台错误，README 能支持其他人独立运行项目；
- 提交者能够现场解释 `params` 与 `query`、`push` 与 `replace`、嵌套路由、导航守卫和懒加载的作用，并能说明这四周每个版本在项目上叠加了什么。
