# 第 4 周学习指南：DOM、事件、存储与异步

## 〇、本周定位

- **承接第 3 周**：上周你用纯 JavaScript 在控制台完成数据处理，并用 `document.querySelector` + `createElement` 把摘要渲染到了页面；本周正式进入浏览器开发。
- 本周内容比前几周多，按两批推进：
  - **第一批（核心线）**：DOM → 事件与事件委托 → `localStorage` → ES Module → 计算器主流程；
  - **第二批（异步线）**：Promise → `fetch` → `async/await` → 历史记录四态。
- 建议先把核心线做扎实再进入异步；异步一时卡住不影响核心功能的完成，详见 [task.md](./task.md) 的「最低可交付标准」。

## 一、本周总学习目标

- 能使用 DOM API 将数据渲染到页面；
- 能通过事件监听响应用户操作；
- 能使用事件委托处理动态元素；
- 能使用 localStorage 持久化数据；
- 能使用 fetch 和 async/await 加载数据并处理各种请求状态；
- 能使用 ES Module 拆分代码。

## 二、本周学习任务

1. 【核心线】练习 DOM 查询、创建、更新和删除操作；
2. 【核心线】使用事件监听处理按键面板、输入框和动态列表的交互；
3. 【核心线】理解事件冒泡，并使用事件委托管理动态生成的按键和历史记录；
4. 【核心线】使用 localStorage 和 JSON 保存计算历史；
5. 【核心线】使用 ES Module 拆分计算逻辑、数据存储、界面渲染和主入口；
6. 【异步线】使用 fetch、async/await 加载示例历史，并处理加载中、加载成功、空数据和加载失败状态；
7. 按照 [task.md](./task.md) 完成原生 JavaScript 简易计算器，并测试非法表达式、括号不匹配、除以零和请求失败等场景；可以先完成核心线，再补异步线。

## 五、完成自检

- 为什么动态生成的按键和列表项适合使用事件委托？
- 为什么不能直接用 `eval` 计算用户输入的表达式？可以怎么替代？
- `2+3*4` 为什么不能从左到右依次算？运算顺序应该怎么保证？
- `-5` 和 `3*-2` 里的 `-` 是同一个运算符吗？程序怎么区分？
- localStorage 为什么不能直接可靠保存对象？
- fetch 返回 404 时是否一定会进入 catch？应该如何判断？
- `textContent` 与 `innerHTML` 在展示用户输入时有什么差异？
- 为什么使用 ES Module 时通常需要本地服务器？
