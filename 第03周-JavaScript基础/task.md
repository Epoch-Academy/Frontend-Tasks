# 第 3 周任务：招新成员数据处理器

## 任务目标

使用 JavaScript 基础语法、函数、数组和对象，先清洗一批有问题的招新原始数据，再完成查询、分组统计和排名，并在控制台输出可逐项核对的结果。

## 上周回顾

- 第 1、2 周你交的都是**静态**页面：HTML 定结构、CSS 定样子，页面内容写死在文件里，用户点了不会有新东西出现。

## 指引

重点关注以下内容：

- `const`、`let`、基本数据类型、`typeof` 判断和类型转换；
- 条件语句（`if`、`switch`）、循环（`for`、`while`、`for...of`）、函数参数与返回值；
- 数组和对象的读取、修改与复制，以及 `forEach`、`map`、`filter`、`find`、`reduce`、`sort`；
- 数据清洗：修复能修的（空格、字符串数字、缺字段），丢弃修不了的（缺关键字段、非法值），并记录每一处问题；
- 分组统计与并列排名（同分同名次，下一名次跳号）；
- 解构赋值、展开运算符、模板字符串、`Object.entries`、`Set`；
- 字符串常用方法、`Math`、`Date`、`JSON` 的基础用法；
- 作用域以及避免污染全局变量；
- 输入边界、空数组和无效数据的处理；
- 使用浏览器控制台定位语法与运行错误；
- 浏览器环境与 `document` 的基本认识，用 `document.querySelector` 选取元素；
- 用 `createElement`、`textContent`、`append` 生成并插入元素（本周只做**最小渲染**，为下周 DOM 打底）。

本周重点仍是数据建模和 JavaScript 逻辑，**不得直接写死统计结果**，所有数字都必须由函数计算得出；页面只做最小渲染，不要求写样式。

## 本轮要求

1. 按上面的目录结构创建 `index.html` 和独立的 `js/main.js`，运行后从控制台查看结果；原始数据直接写在 `js/main.js` 顶部，不需要额外的数据文件。
2. 准备不少于 16 条原始数据，每条至少包含 `id`、姓名（`name`）、年级（`grade`）、方向（`direction`）、笔试成绩（`score`）、是否提交作业（`submitted`），并**故意混入下面 5 类问题，每类至少 1 处（合计不少于 5 处）**：

   | 问题类型 | 具体要求 | 清洗策略 |
   | --- | --- | --- |
   | 类型不对 | 成绩写成字符串（如 `'85'`） | 能转成合法数字就**修复** |
   | `id` 重复 | 至少两条数据 `id` 相同 | 保留第一条，其余**丢弃**并记录 |
   | 缺字段 | 如缺 `submitted`、缺姓名 | 缺关键字段（姓名 / 方向）**丢弃**；缺可推断字段可**修复** |
   | 方向为空 | `''` 或全是空格 | 去掉空格后为空则**丢弃** |
   | 成绩非法 | 超出 0～100（如 `105`）、不是数字（如 `'abc'`）、字符串带多余空格（如 `' 85 '`） | 带空格可**修复**；超范围或无法转数字则**丢弃** |

   数据必须真的交给清洗函数处理，不能自己先手工改好。字段名照抄下面这条样例，方便助教逐项核对：

   ```js
   // 一条「干净」的数据：id 用字符串、submitted 用布尔值
   { id: 'm01', name: '张一', grade: '大一', direction: '前端', score: 85, submitted: true }

   // 下面这些才是要被清洗的（每类至少 1 处，共不少于 5 处）：
   { id: 'm02', name: '  ', grade: '大二', direction: '后端', score: ' 85 ', submitted: true }  // 成绩带空格（可修复）+ 姓名全空格（丢弃）
   { id: 'm01', name: '张二', grade: '大一', direction: '前端', score: 90, submitted: false }    // id 与 m01 重复（丢弃并记录）
   { id: 'm03', name: '李三', grade: '大三', direction: '', score: 105, submitted: true }        // 方向为空（丢弃）+ 成绩超范围（丢弃）
   { id: 'm04', name: '王四', grade: '大一', direction: '前端', score: 'abc' }                   // 成绩非数字（丢弃）+ 缺 submitted（按缺可推断字段处理）
   ```

   字段口径：`id`、`name`（姓名）、`grade`（年级）、`direction`（方向）、`score`（笔试成绩）、`submitted`（是否提交作业），共 6 个；清洗后有效数据里的 `score` 必须是数字类型。
3. 编写并调用以下函数（全部通过参数接收数据，不得只操作某个固定的全局数组）：
   - 清洗原始数据，返回 `{ members, issues }`：`members` 是干净数据，`issues` 是一句一条的问题记录；
   - 根据 `id` 查找成员；
   - 筛选指定方向的成员；
   - 筛选已提交作业且成绩达到指定分数的成员；
   - 计算平均成绩；
   - 按方向分组，得到 `{ 方向: [成员...] }`；
   - 计算各方向平均分；
   - 按成绩从高到低返回新数组；
   - 生成带名次的排名数组，**同分同名次，下一名次跳号**（例如 95、95、90 → 1、1、3）；
   - 生成包含姓名、方向和录取建议的新数组。
4. 每个函数只做一件事；不读写全局变量；不得修改传入的数组；分数、阈值、取值范围等提取成常量；录取建议用 `if / else if` 或 `switch` 表达，不要写多层嵌套三元表达式。
5. **数值口径统一**（助教会按这个标准核对，请照做）：
   - 所有平均分保留 **1 位小数**，用 `Math.round(值 * 10) / 10`（例如 82.46 → `82.5`）；
   - 及格 / 录取建议的阈值提取成常量，建议：平均分与笔试成绩 ≥ 80 为「建议录取」，60～79 为「待定」，< 60 为「不建议」；
   - 排名按成绩从高到低；`105`、`'abc'` 这类数据在清洗阶段就已丢弃，不应出现在统计里。
6. 清洗时对"已修复"和"已丢弃"的数据都要在控制台给出提示（`console.warn` 或问题日志），并在末尾汇总：原始多少条、有效多少条、发现多少处问题。
7. 关键结果统一用 `console.log(JSON.stringify(结果, null, 2))` 打印，方便逐项核对；排序前后要能看出原数组顺序没有变化（也就是排序函数返回的是**新数组**）。
8. 至少分别使用一次：`switch`、`for...of`、函数表达式（或默认参数）、解构赋值、展开运算符、模板字符串、常用字符串方法、`Math` 或 `Date`、`JSON.stringify` 或 `JSON.parse`。
9. 对空数组、找不到成员、分数不是有效数字等情况给出合理结果并提示，程序不能崩溃。
10. 控制台输出格式参考（数值请自行计算）：

   ```text
   原始数据 20 条，清洗后有效 15 条，共发现 11 处问题。
   平均成绩： 82.5
   各方向统计：
   [ { "direction": "前端", "count": 5, "average": 84.2 }, ... ]
   排名：
   [ { "name": "某某", "score": 95, "rank": 1 }, ... ]
   ```

11. 把摘要（有效人数、平均分、各方向人数、最高分等）渲染到页面上：
    a. 在 `index.html` 里准备一个容器元素（如 `<ul id="summary">` 或一个 `section`）作为挂载点；
    b. 用 `document.querySelector` 取到它，再用 `createElement` + `textContent` + `append` 把每条摘要作为独立元素插入；
    c. **不要用 `innerHTML` 拼接字符串**；本周只体会「用 JS 生成页面元素」，不要求写样式。
12. 在 `README.md` 中列出各函数的名称、参数、返回值和至少一个调用示例，并用 Git 提交本周代码。
13. 选做加分项：写一个 `parseMembersFromText(text)`，把 `"姓名,方向,成绩,是否提交"` 这种多行文本解析成对象数组。
14. 选做预热：用 `setTimeout(() => console.log('延迟执行'), 1000)` 让一段提示延迟 1 秒再打印，先感受「代码不是走到哪就立刻执行完」，为下周的异步做铺垫。

## 完成标准

- 页面加载后控制台无语法错误，页面能显示摘要；
- 摘要通过 `createElement` + `textContent` 渲染，没有用 `innerHTML` 拼接数据；
- 清洗后有效数据不少于 10 条，每一处被修复或被丢弃的数据都有对应提示；
- 平均分、各方向人数、各方向平均分、筛选结果正确；
- 并列名次处理正确：同分同名次，且下一名次跳号；
- 原始数组在排序函数执行前后保持原顺序，传入的数组没有被修改；
- 找不到成员、空数据、非法分数时程序不崩溃且有提示；
- 关键结果以 JSON 格式输出，助教可以逐项核对；
- 代码具有基本缩进、命名规范和必要注释，重复逻辑得到适当封装；
- `README.md`（文件名全小写）内容完整，并已通过 Git 提交；
- 能现场说明 `const` 与 `let`、`map` 与 `forEach`、引用数据复制与直接赋值的区别，以及并列名次的实现思路。
