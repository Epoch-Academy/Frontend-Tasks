# 第 3 周任务：招新成员数据处理器

## 任务目标

使用 JavaScript 基础语法、函数、数组和对象，先清洗一批有问题的招新原始数据，再完成查询、分组统计和排名，并在控制台输出可逐项核对的结果。

## 指引

重点关注以下内容：

- `const`、`let`、基本数据类型、`typeof` 判断和类型转换；
- 条件语句（`if`、`switch`）、循环（`for`、`while`、`for...of`）、函数参数与返回值；
- 数组和对象的读取、修改与复制，以及 `forEach`、`map`、`filter`、`find`、`reduce`、`sort`；
- 数据清洗：修复能修的（空格、字符串数字、缺字段），丢弃修不了的（缺关键字段、非法值），并记录每一处问题；
- 分组统计与并列排名（同分同名次，下一名次跳号）；
- 解构赋值、展开运算符、模板字符串、`Object.entries`、`Set`；
- 字符串常用方法、`Math`、`Date`、`JSON` 的基础用法；
- 作用域以及避免污染全局变量；
- 输入边界、空数组和无效数据的处理；
- 使用浏览器控制台定位语法与运行错误；
- 浏览器环境与 `document` 的基本认识，用 `document.querySelector` 选取元素；
- 用 `createElement`、`textContent`、`append` 生成并插入元素（本周只做**最小渲染**，为下周 DOM 打底）。

本周重点仍是数据建模和 JavaScript 逻辑，**不得直接写死统计结果**，所有数字都必须由函数计算得出；页面只做最小渲染，不要求写样式。

## 本轮要求

1. 按上面的目录结构创建 `index.html` 和独立的 `js/main.js`，运行后从控制台查看结果；原始数据直接写在 `js/main.js` 顶部，不需要额外的数据文件。
2. 准备不少于 16 条原始数据，每条至少包含 `id`、姓名（`name`）、年级（`grade`）、方向（`direction`）、笔试成绩（`score`）、是否提交作业（`submitted`），并**故意混入下表 6 类问题，每类至少 1 处（合计不少于 5 处）**：

   | 问题类型 | 具体要求 | 清洗策略 |
   | --- | --- | --- |
   | 类型不对 | 成绩写成字符串（如 `'85'`、`' 85 '`） | **修复**：`Number(去空格后的字符串)`，变成数字类型 |
   | `id` 重复 | 至少两条数据 `id` 相同 | 保留第一条，其余**丢弃**并记录 |
   | 缺字段 | 缺 `submitted`、或姓名缺失 / 全空格 | 缺关键字段（姓名 / 方向）**丢弃**；缺 `submitted` **修复为 `false`**（见下方「修复口径」） |
   | 方向为空 | `''` 或全是空格 | 去掉空格后为空则**丢弃** |
   | 成绩非法 | 超出 0～100（如 `105`）、不是数字（如 `'abc'`） | **丢弃** |
   | 姓名有空白 | 如 `'张一 '`、`' 冯十二 '` | **修复**：`trim()` 去掉首尾空格后继续使用 |

   **每类问题至少出现 1 处、合计不少于 5 处**，并且**至少要有 1 处是"修复"、1 处是"丢弃"**——两类都要能在控制台里看到，否则等于没验证清洗策略。

   #### 修复口径（各周统一，助教按这个核对）

   怕数据太脏可以自己多造几条，但"修复成什么值"必须固定下来，否则名次和平均分对不上：

   | 原始情况 | 修复为 | 是否记一条 issue |
   | --- | --- | --- |
   | `submitted` 缺失（`undefined` / `null` / 非布尔值） | `submitted: false`（**按"未提交"处理**） | 是，写「修复」 |
   | 成绩是字符串但能转成合法数字 | 数字类型（去掉首尾空格后 `Number()`） | 是，写「修复」 |
   | 姓名为字符串但带首尾空格 | `trim()` 后的姓名 | 是，写「修复」 |
   | 姓名缺失 / 全空格、方向为空、成绩超范围或无法转数字、`id` 重复 | 不修复 | 是，写「丢弃」 |

   > `submitted` 缺失时**不要**补成 `true`：补成"已提交"会把一条没有依据的数据算进「已提交且成绩达标」的筛选结果里，属于替数据编造事实；补成 `false` 只影响它是否被那条筛选命中，不会污染平均分和名次。

   数据必须真的交给清洗函数处理，不能自己先手工改好。字段名照抄下面的样例：

   ```js
   // 一条「干净」的数据：id 用字符串、submitted 用布尔值
   { id: 'm01', name: '张一', grade: '大一', direction: '前端', score: 85, submitted: true }
   ```

   #### 可选：固定样例数据（想省事就直接照抄这 16 条）

   自己造数据完全可以。若希望**数字能和文档下方的输出样例对上、方便助教逐项核对**，可直接照抄这 16 条——它们覆盖了上表全部 6 类问题，并且每类只出现一次，方便你逐条定位：

   ```js
   const rawMembers = [
     { id: 'm01', name: '张一',   grade: '大一', direction: '前端', score: 85,      submitted: true  },
     { id: 'm02', name: '   ',    grade: '大二', direction: '后端', score: ' 85 ',  submitted: true  }, // 姓名全空格        -> 丢弃
     { id: 'm03', name: '李三',   grade: '大三', direction: '前端', score: 105,     submitted: true  }, // 成绩超出 0~100    -> 丢弃
     { id: 'm04', name: '王四',   grade: '大一', direction: '前端', score: 92                        }, // 缺 submitted      -> 修复为 false
     { id: 'm05', name: '赵五',   grade: '大二', direction: '后端', score: 'abc',   submitted: true  }, // 成绩无法转数字     -> 丢弃
     { id: 'm06', name: '钱六',   grade: '大一', direction: '算法', score: ' 78 ', submitted: false }, // 成绩带空格        -> 修复为 78
     { id: 'm07', name: '孙七',   grade: '大四', direction: '   ', score: 88,      submitted: true  }, // 方向全空格        -> 丢弃
     { id: 'm08', name: '周八',   grade: '大二', direction: '前端', score: 59.4,    submitted: true  },
     { id: 'm09', name: '吴九',   grade: '大三', direction: '后端', score: 95,      submitted: true  },
     { id: 'm10', name: '郑十',   grade: '大一', direction: '算法', score: 95,      submitted: false },
     { id: 'm11', name: '王十一', grade: '大二', direction: '前端', score: 90,      submitted: true  },
     { id: 'm12', name: ' 冯十二 ', grade: '大一', direction: '后端', score: 0,      submitted: false }, // 姓名带首尾空格 -> 修复后保留
     { id: 'm13', name: '陈十三', grade: '大三', direction: '算法', score: 100,     submitted: true  },
     { id: 'm14', name: '褚十四', grade: '大二', direction: '前端', score: 61,      submitted: true  },
     { id: 'm06', name: '卫十五', grade: '大一', direction: '后端', score: 88,      submitted: true  }, // id 与 m06 重复 -> 丢弃

   ```

   > 注意 `m04` 与 `m05` 的区别：`m04` 的成绩是**合法数字**、只缺 `submitted`（→ 修复后保留），`m05` 的成绩是 `'abc'`（→ 直接丢弃）。这样「修复缺字段」这条规则才真的会被触发、也能被看见。

   字段口径：`id`、`name`（姓名）、`grade`（年级）、`direction`（方向）、`score`（笔试成绩）、`submitted`（是否提交作业），共 6 个；清洗后有效数据里的 `score` 必须是数字类型、`submitted` 必须是布尔类型。
3. 编写并调用以下函数（全部通过参数接收数据，不得只操作某个固定的全局数组）：
   - 清洗原始数据，返回 `{ members, issues }`：`members` 是干净数据，`issues` 是一句一条的问题记录，**每条都要标出是「修复」还是「丢弃」、针对哪条数据、原因是什么**；
   - 根据 `id` 查找成员；
   - 筛选指定方向的成员；
   - 筛选已提交作业且成绩达到指定分数的成员；
   - 计算平均成绩；
   - 按方向分组，得到 `{ 方向: [成员...] }`；
   - 计算各方向平均分；
   - 按成绩从高到低返回新数组；
   - 生成带名次的排名数组，**同分同名次，下一名次跳号**（例如 95、95、90 → 1、1、3；95、95、95 → 2、2、2，紧接着下一位是 5）；
   - 生成包含姓名、方向和录取建议的新数组。
4. 每个函数只做一件事；不读写全局变量；不得修改传入的数组；分数、阈值、取值范围等提取成常量；录取建议用 `if / else if` 或 `switch` 表达，不要写多层嵌套三元表达式。
5. **数值口径统一**（助教会按这个标准核对，请照做）：
   - 所有平均分保留 **1 位小数**，用 `Math.round(值 * 10) / 10`（例如 82.46 → `82.5`）；
   - 及格 / 录取建议的阈值提取成常量，建议：平均分与笔试成绩 ≥ 80 为「建议录取」，60～79 为「待定」，< 60 为「不建议」；
   - 排名按成绩从高到低；`105`、`'abc'` 这类数据在清洗阶段就已丢弃，不应出现在统计里。
6. 清洗时对"已修复"和"已丢弃"的数据都要在控制台给出提示（`console.warn` 或问题日志），并在末尾汇总：原始多少条、有效多少条、发现多少处问题。
7. 关键结果统一用 `console.log(JSON.stringify(结果, null, 2))` 打印，方便逐项核对；排序前后要能看出原数组顺序没有变化（也就是排序函数返回的是**新数组**）。
8. 至少分别使用一次：`switch`、`for...of`、函数表达式（或默认参数）、解构赋值、展开运算符、模板字符串、常用字符串方法、`Math` 或 `Date`、`JSON.stringify` 或 `JSON.parse`。
9. 对空数组、找不到成员、分数不是有效数字等情况给出合理结果并提示，程序不能崩溃。
10. 控制台输出格式参考（**下面的数字来自第 2 条的「固定样例数据」，照抄那 16 条就能得到完全一样的结果**；自己造的数据请换成自己的真实计算结果，格式保持一致）：

   ```text
   原始数据 16 条，清洗后有效 11 条，共发现 9 处问题（修复 4 处，丢弃 5 处）。
   平均成绩： 77.3
   各方向统计：
   [ { "direction": "前端", "count": 5, "average": 77.5 }, ... ]
   排名：
   [ { "name": "陈十三", "score": 100, "rank": 1 }, { "name": "吴九", "score": 95, "rank": 2 }, ... ]
   最高分： 100
   ```

   用「固定样例数据」得到的完整结果如下，可用来逐项核对（自己造的数据结果不同是正常的，但**结构必须一致**）：

   | 指标 | 结果 |
   | --- | --- |
   | 原始 / 有效 / 问题数 | 16 条 → 11 条，9 处问题（修复 4 处、丢弃 5 处） |
   | 平均成绩（1 位小数） | `77.3` |
   | 各方向统计 | 前端 5 人 / 77.5；算法 4 人 / 92.0；后端 2 人 / 47.5 |
   | 最高分 | `100`（陈十三） |
   | 已提交人数 | `7` 人 |
   | 名次（同分同名次、下一名次跳号） | 100→1；**95、95、95→2、2、2**；92→**5**（不是 3、不是 4）；90→6；85→7；78→8；61→9；59.4→10；0→11 |

   > 上面「95 并列第 2、下一位直接跳到第 5」这一行是**必须对**的：助教首先就看这里。整理成"排名"数组时请按 `score` 从高到低，且**只跳号、不补位**。
   >
   > 各方向统计里**方向的先后顺序不限**（按出现顺序、按名称排序都可以），只要每个方向的人数和平均分正确即可。

   逐条问题记录的写法参考（一条问题一行，修复 / 丢弃都要写清是谁、为什么）：

   ```text

   - 丢弃 m03：成绩非法（105）
   ```

11. 把摘要（有效人数、平均分、各方向人数、最高分等）渲染到页面上：
    a. 在 `index.html` 里准备一个容器元素（如 `<ul id="summary">` 或一个 `section`）作为挂载点；
    b. 用 `document.querySelector` 取到它，再用 `createElement` + `textContent` + `append` 把每条摘要作为独立元素插入；
    c. **不要用 `innerHTML` 拼接字符串**；本周只体会「用 JS 生成页面元素」，不要求写样式。
12. 选做加分项：写一个 `parseMembersFromText(text)`，把 `"姓名,方向,成绩,是否提交"` 这种多行文本解析成对象数组。
13. 选做预热：用 `setTimeout(() => console.log('延迟执行'), 1000)` 让一段提示延迟 1 秒再打印，先感受「代码不是走到哪就立刻执行完」，为下周的异步做铺垫。

## 完成标准

- 页面加载后控制台无语法错误，页面能显示摘要；
- 摘要通过 `createElement` + `textContent` 渲染，没有用 `innerHTML` 拼接数据；
- 清洗后有效数据不少于 10 条；**修复与丢弃两类都至少各有 1 处**，每一处被修复或被丢弃的数据都有对应提示（写清是哪条、什么原因）；
- 若使用第 2 条的「固定样例数据」，原始 16 条 → 有效 11 条 / 9 处问题（修复 4、丢弃 5）、平均分 `77.3`、最高分 `100` 必须完全一致；
- 平均分、各方向人数、各方向平均分、筛选结果正确；
- 并列名次处理正确：同分同名次，且下一名次跳号（用固定样例数据时应得到 95→2、2、2，92→5）；
- 原始数组在排序函数执行前后保持原顺序，传入的数组没有被修改；
- 找不到成员、空数据、非法分数时程序不崩溃且有提示；
- 关键结果以 JSON 格式输出，助教可以逐项核对；
- 代码具有基本缩进、命名规范和必要注释，重复逻辑得到适当封装；
- 能现场说明 `const` 与 `let`、`map` 与 `forEach`、引用数据复制与直接赋值的区别，以及并列名次的实现思路。
